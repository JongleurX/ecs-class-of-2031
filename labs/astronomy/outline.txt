How to keep the rule structure predictable
You asked a really important design question: if the 3-digit and 5-digit versions use different rules, how do students see a consistent pattern?

I would use a rule menu that stays the same from puzzle to puzzle. The exact numbers change, but the types of rules stay stable.

Suggested rule menu

Each signal puzzle is built from these rule types:

Digit property rule
a digit is prime / even / odd
No-repeat rule
all digits are different
Local relationship rule
one digit is 3 more than another
one digit is 1 more than another
one digit is twice another
Global checksum rule
the sum of digits is a certain value
the whole number is divisible by some number
the alternating sum has a certain remainder
So the structure is predictable:

one or two digit facts
one or two relationship facts
one checksum fact
That gives students a repeatable method:

list what each rule tells you
combine rules
eliminate impossible cases
verify the final candidate

def ok(s):
    d = [int(c) for c in s]
    return (
        len(set(d)) == 5 and
        d[1] == d[0] + 3 and
        d[2] in [2, 3, 5, 7] and
        d[3] == d[2] + 1 and
        d[4] == 2 * d[3] and
        sum(d) == 24
    )

for n in range(10000, 100000):
    s = str(n)
    if ok(s):
        print(s)
This is short, clean, and readable.

Can Python generate a rule set with exactly one solution?
Yes — absolutely.

But I’d separate this into two different programs:

1. Student solver

Very short, simple, elegant.

2. Teacher generator

A somewhat longer program you use beforehand to create puzzles.

The generator idea is:

Pick a hidden signal ID, like 58236
Build a pool of possible rules that are true for that ID
Test combinations of those rules
Keep a set of rules only if exactly one candidate satisfies them
So yes, the answer is definitely yes.

The generator algorithm, conceptually
Suppose the secret answer is 58236.

You could create a pool of candidate rules such as:

all digits are different
second digit is 3 more than first
third digit is prime
fourth digit is 1 more than third
fifth digit is twice the fourth
sum of digits is 24
first digit is odd
last digit is even
whole number is divisible by 3
first digit is greater than third
Then the program tries combinations of 3, 4, 5, or 6 rules and asks:

“How many signal IDs satisfy all these rules?”
if the answer is more than 1, the rule set is too weak
if the answer is exactly 1, success
if the answer is 0, the rules are contradictory

from itertools import combinations

def all_codes(length):
    start = 10 ** (length - 1)
    end = 10 ** length
    return [str(n) for n in range(start, end)]

def make_rules(answer):
    d = [int(c) for c in answer]
    return [
        ("no repeats", lambda s: len(set(s)) == len(s)),
        ("second is 3 more than first",
         lambda s: int(s[1]) == int(s[0]) + 3),
        ("third is prime",
         lambda s: int(s[2]) in [2, 3, 5, 7]),
        ("fourth is 1 more than third",
         lambda s: int(s[3]) == int(s[2]) + 1),
        ("fifth is twice the fourth",
         lambda s: int(s[4]) == 2 * int(s[3])),
        ("sum is 24",
         lambda s: sum(int(c) for c in s) == 24),
    ]

def find_unique_rule_set(answer):
    codes = all_codes(len(answer))
    rules = make_rules(answer)

    for k in range(3, len(rules) + 1):
        for combo in combinations(rules, k):
            matches = [
                s for s in codes
                if all(rule(s) for _, rule in combo)
            ]
            if matches == [answer]:
                return [name for name, _ in combo]

    return None

One important practical note
If you want the generator to work well, the best strategy is:

keep a menu of simple rule templates
generate rules from the chosen answer
search for the smallest subset that gives a unique solution
That way the puzzle stays:

human-solvable
mathematically neat
code-checkable
not overloaded with arbitrary facts
